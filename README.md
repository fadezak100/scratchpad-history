# Scratchpad History

CS886 (Fall 2026) course project: **how much scratchpad history do transformers need to learn
and generalize?**

We train a small transformer from scratch on cycle reachability (does following edges from node
`s` reach node `t`?) and vary only how much of its own scratchpad the model sees when it writes
the next state:

- **full history** (`--k 0`): the question and every earlier state;
- **last 4 states** (`--k 4`) and **last 2 states** (`--k 2`);
- **latest state only** (`--k 1`), the inductive scratchpad.

Everything else (graphs, model, optimizer, step budget, test sets) is the same in every condition.

## Reproducing the reported results

There is no dataset to download. Every training and test problem is generated by the code from
fixed seeds (`src/scratchpad/task.py`), so the commands below are all that is needed.

### 1. Install

Requires Python ≥ 3.10. The reported runs used Python 3.11, PyTorch 2.14.1 and transformers 5.22.2.
With [uv](https://docs.astral.sh/uv/):

```bash
uv venv --python 3.11 .venv
source .venv/bin/activate
uv pip install -e ".[dev]"
```

With plain `pip`, create and activate a Python ≥ 3.10 virtual environment, then run
`pip install -e ".[dev]"`. Dependencies are listed in `pyproject.toml`. Training uses a CUDA GPU
if there is one, then Apple `mps`, then the CPU.

### 2. Check the install

```bash
pytest                            # 64 tests, a few seconds
python scripts/smoke_overfit.py   # memorizes 100 problems (~3 min)
```

### 3. Experiment A: four history lengths at 24 nodes (12 runs)

24 nodes, train on 6-step problems, test on 6, 8, 10 and 12 steps, new training problems at every
step, at most 50,000 optimizer steps, 4 conditions × seeds 0, 1, 2.

```bash
for seed in 0 1 2; do for k in 0 4 2 1; do
  python -m scratchpad.train --k $k --seed $seed --fresh \
      --n-nodes 24 --train-steps 6 --test-steps 6,8,10,12 \
      --max-steps 50000 --eval-every 500 --results-dir results/exp_a
done; done
```

Each run took 1.5 to 7.7 hours on a 10 GB slice of an NVIDIA H100, so the runs are best started in
parallel. On a Slurm cluster the same 12 runs are one job array:

```bash
sbatch --account=<your-account> --time=12:00:00 \
    --export=ALL,N_NODES=24,RESULTS_DIR=results/exp_a scripts/cluster/train_array.sh
```

`scripts/cluster/train_array.sh` requests a whole H100 by default; edit its `--gres` line for your
cluster. `scripts/cluster/setup_env.sh` builds the environment inside the job and assumes the
Digital Research Alliance of Canada module system.

### 4. Experiment B: limited training data at 8 nodes (24 runs)

8 nodes, train on 3-step problems, test on 3 to 6 steps, a fixed training set of 250, 1,000, 4,000
or 16,000 problems, at most 4,000 optimizer steps, latest-only and full history × seeds 0, 1, 2.
These are the defaults in `src/scratchpad/config.py`.

```bash
python scripts/run_sweep.py --dry-run --results-dir results/exp_b   # print the 24 runs
python scripts/run_sweep.py --results-dir results/exp_b            # run them (minutes each on a GPU)
```

The sweep skips runs that are already finished, so it can be stopped and restarted. The Slurm
version is `scripts/cluster/sweep_8nodes_array.sh`.

### 5. Attention measurements

```bash
for run in results/exp_a/*/ results/exp_b/*/; do
  python -m scratchpad.attention --run "$run"       # writes attention.json into the run folder
done
```

### 6. Tables and figures

```bash
python scripts/threshold_table.py --results-dir results/exp_a       # runs that learned, steps to 95%
python scripts/plot_training_curves.py --results-dir results/exp_a  # training-curve figure
python scripts/make_plots.py --results-dir results/exp_a            # summary.csv: accuracy per run and test length
python scripts/make_plots.py --results-dir results/exp_b            # summary.csv and accuracy by training-set size
```

`summary.csv` holds the held-out trace accuracy of every run at every test length; each run's
`attention.json` holds the edge-attention share of every head. Figures are written to
`<results-dir>/figures/`.

### What to expect

The seeds fix the training problems, the initial weights and the test sets. GPU arithmetic is not
bit-for-bit reproducible across hardware and library versions, so step counts and a run's exact
accuracy can differ from the report; which runs learn within the step limit can also differ.

## One training run

```bash
python -m scratchpad.train --k 1 --n-train 16000 --seed 0   # latest state only, 8-node defaults
```

| Flag | Meaning | Default |
|---|---|---|
| `--k` | history length; `0` = full history, `1` = latest state only | `0` |
| `--seed` | seed for the training problems and the initial weights | `0` |
| `--n-train` | size of the fixed training set (ignored with `--fresh`) | `16000` |
| `--fresh` | generate new training problems at every step | off |
| `--n-nodes`, `--train-steps`, `--test-steps` | task size and lengths | 8, 3, `3,4,5,6` |
| `--max-steps`, `--eval-every` | optimizer step limit and evaluation interval | 4000, 250 |
| `--n-layers`, `--n-heads`, `--hidden-size`, `--ffn-size` | model shape | 4, 4, 256, 1024 (4.2M parameters) |
| `--results-dir` | where run folders are written | `results` |
| `--device` | `auto`, `cpu`, `mps` or `cuda` | `auto` |

A run writes `results/<run_id>/` (for example `k1_n16000_s0` or `kfull_n16000_s0`) containing
`config.json` (the full configuration), `metrics.json` (the training log and held-out accuracy;
written last, so its presence marks the run as finished) and `model.pt` (the trained weights). All
other settings are dataclass defaults in `src/scratchpad/config.py`.

## Layout

```
src/scratchpad/
  config.py     defaults for the task, model and training
  task.py       graph generator and oracle trace
  tokens.py     vocabulary, encode/decode
  formats.py    problem → training examples for a given history length
  data.py       datasets, padding, held-out sets
  model.py      the small Llama-style model
  train.py      training loop and CLI
  evaluate.py   step-by-step solving and scoring
  attention.py  edge-attention share and CLI
scripts/        smoke_overfit.py, run_sweep.py, make_plots.py, threshold_table.py, plot_training_curves.py
scripts/cluster Slurm job scripts
tests/          pytest suite
results/        run outputs (not committed)
papers/         source papers (not committed)
```
